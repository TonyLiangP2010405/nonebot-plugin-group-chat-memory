# 好感榜前 3 回复附图

日期：2026-11-05

## 目标

好感榜前 3 名的群友发言触发回复时，在文字回复后补一张与当前对话相关的表情包；SUPERUSER 发言 100% 触发并附图。榜内第 4 名及以后完全保持现状——该回就回，不附图。

## 现状

- 好感榜触发已存在：`/好感概率`（默认 30%）对**所有**榜内成员生效，实际概率取 `max(群概率, 好感概率)`，且该路径豁免每小时限流。
- `AffectionLeaderboard` 把 `service.ranking()` 的结果拍平成 `frozenset`，丢掉了名次；`ranking()` 返回的条目自带 `rank`，顺序即名次。
- 回复统一经 `ReplyCoordinator` 异步排队，`reply()` 只发送纯文本。
- 表情包接口使用已实测可用的接口盒子（apihz）：`https://cn.apihz.cn/api/img/apihzbqb.php`，`type=2` 按关键词检索，`words` 最多 10 个汉字，`limit` 最多 20。

## 触发规则

| 发言者 | 是否触发 | 带图 |
|---|---|---|
| SUPERUSER | 100% | 是 |
| 好感榜第 1–3 名 | 沿用 `/好感概率` 与群概率的较大者 | 是 |
| 好感榜第 4 名及以后 | 与现在一致 | 否 |
| 必回名单成员 | 与现在一致 | 否 |
| @ / 回复 Bot、非纯文本消息 | 与现在一致 | 否 |

- 前 3 名受 `/好感开关` 控制：关闭后既不触发也不带图。
- SUPERUSER 不受好感开关、好感概率、每秒限流影响，任何群都 100% 触发。
- 前 3 名与 SUPERUSER 触发时不占用每小时请求名额（与现有好感路径一致）。
- 只做一次随机判定，不新增第二次掷骰子。

## 数据流

`models.Message` 增加 `attach_meme: bool = False`。默认值保证所有现有构造调用不变，持久化只写入 `add_message` 里显式列出的字段，不受影响。

`handle_group_message` 判定完成后，把 `attach_meme` 置位再交给 `coordinator.submit()`；`reply()` 发完文字后按该标记取图并发送。

## 表情包取用

新增 `meme.py` 的 `MemeProvider`：

- 关键词：取 LLM 回复文本，去掉标点与空白，只保留中英文和数字，截取前 10 个字符；为空则不发图。
- 请求：`GET {api_url}?id=..&key=..&type=2&words=..&page=1&limit=6`，超时 10 秒。
- 选图：从 `res` 里随机取一条。
- 节流：全局串行 + 最小间隔 6.5 秒（对应 10 次/分钟的额度）。
- 缓存：关键词 → 图片 URL，TTL 10 分钟，最多 200 条，超出按插入顺序淘汰。
- 失败：`code != 200`、`res` 为空、网络异常或超时都返回 `None`，只记 warning，不影响文字回复。

缓存命中不占用节流额度；未命中且需要等待时，图片会晚于文字几秒到达，属于可接受代价。

## 配置

环境变量，不放进运行时配置命令：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `GROUP_CHAT_MEMORY_MEME_ENABLED` | `true` | 总开关 |
| `GROUP_CHAT_MEMORY_MEME_API_URL` | apihz 官方库地址 | 便于以后换接口 |
| `GROUP_CHAT_MEMORY_APIHZ_ID` | 空 | 接口盒子数字 ID |
| `GROUP_CHAT_MEMORY_APIHZ_KEY` | 空 | 接口盒子通讯 KEY，`SecretStr` |

ID 或 KEY 为空时功能静默跳过，只记一次 debug 日志，不影响其他逻辑。

## 方案与取舍

### 消息模型加标记（已选择）

改动集中在 `models.py`、`handlers.py`、`reply()` 三处，概率判定仍只有一处，现有测试几乎不用改。代价是消息模型多一个业务字段，但 `Message` 本身就是“待写记忆的一条消息”载体，Bot 自己的回复也在用，默认值保证旧调用不变。

### 协调器携带标签

队列元素改为 `(Message, tag)`，语义更干净，但 `replies.py` 的公共接口和两百多行测试都要跟着改，收益不抵成本。

### 发送时重新判断

`reply()` 里重新查榜和 SUPERUSER 配置。零结构改动，但无法知道当初是哪一档触发的，普通概率触发会被误判成好感触发而附图，行为不可靠，不采用。

## 失败处理

- 好感插件缺失或读取失败：`top_members` 返回空，前 3 逻辑退化为不触发，SUPERUSER 不受影响。
- 取图失败：只发文字，不重试，不向群里报错。
- 发送图片抛异常：捕获并记 warning，记忆写入照常完成。

## 测试

- `AffectionLeaderboard.top_members`：按 `rank` 取前 3、名次缺失时按列表顺序、与 `is_member` 共用同一份缓存。
- `MemeProvider`：关键词清洗与截断、缓存命中不发请求、失败返回 `None`、空结果返回 `None`、节流间隔。
- handler：SUPERUSER 100% 且置位、前 3 概率触发置位、第 4 名不置位、@ 与回复消息不置位、必回名单不置位。
- `reply()`：标记为真时发文字加图片，取图失败只发文字。

## 留给实现者的决定

- 节流用全局 `asyncio.Lock` + 单调时钟实现，不引入新依赖。
- 缓存用普通 dict + 过期时间，不引入 LRU 库。
- 日志在取图失败时按关键词去重，避免接口挂掉后刷屏。
