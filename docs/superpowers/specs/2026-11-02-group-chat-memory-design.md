# 群聊对话与长期记忆插件设计

日期：2026-11-02

## 目标与背景

创建一个独立的 NoneBot2 群聊插件。群友可以通过 @Bot 或回复 Bot 的消息进行连续对话；Bot 也会按每个群独立配置的概率随机参与对话。聊天模型由插件直接请求 OpenAI 兼容 API，默认模型名为用户提供的 DeepSeek V4.1 Flash，实际模型标识可配置。

插件保存群内所有群友的文本聊天，并按群建立共享长期记忆。记忆用于延续群内话题和共同经历，不建立跨群个人画像。普通消息的记忆写入不得阻塞 Bot 回复。

## 已确定的需求

- 每个群一份共享记忆，所有查询和清除操作都必须按群号隔离。
- 保存群内所有群友的文本消息，而不只保存与 Bot 的对话；Bot 自己发出的回复也保存，以维持对话上下文。
- @Bot 或回复 Bot 的消息必定触发回复。
- 普通群消息按概率随机触发回复，默认概率为 0%。
- 随机回复概率按群独立设置并持久化，只有 NoneBot SUPERUSER 可以修改。
- 建议命令为 `/回复概率 5`，表示将当前群随机回复概率设为 5%；合法范围为 0～100，支持一位小数。无参数时查询当前群概率。
- 提供 `/清空群记忆` 命令，仅 SUPERUSER 可执行，只清除当前群的原始消息、长期向量和相关状态，不修改概率配置。
- 聊天 API 使用独立的 `base_url`、`api_key`、`model` 配置，不依赖 opencode 常驻运行。
- Embedding 默认使用硅基流动的 OpenAI 兼容接口，首选 `BAAI/bge-m3`；地址、密钥和模型名均可配置。

## 非目标

- 首版不保存图片、语音、文件等内容本身；非文本消息不进入长期记忆，也不随机触发回复。
- 不跨群检索记忆，不建立群友个人画像。
- 不实现记忆管理网页、可视化后台或多模态 Embedding。
- 不承诺永久保存所有向量；后续可增加按时间或容量清理策略，但首版不自动删除群聊原文。

## 总体方案

采用 SQLite + sqlite-vec 的本地单文件方案。SQLite 保存原始消息、分块文本、群配置和待处理状态，sqlite-vec 保存并检索向量，不需要 Qdrant 等额外服务。

每次 Bot 回复使用两类上下文：

1. 最近对话：直接读取当前群最近约 20 条消息，低延迟且保留话题连续性。
2. 长期记忆：将本次输入转换为查询向量，只从当前群检索最相关的 3～5 个历史片段。

最终提示词由系统提示、检索到的长期记忆、最近消息和当前输入组成。所有记忆片段带群号、时间范围和发言者显示名，避免模型混淆来源。

## 记忆写入

- 普通群文本消息到达后，先异步写入 SQLite 原始消息表，再进入待分块状态。
- 每积累约 10 条消息组成一个记忆片段；片段保留发言者、时间和原文顺序。
- 分块后批量请求一次 Embedding API，将向量与片段关联，并标记完成。
- Embedding 请求在后台执行，不阻塞消息接收和 Bot 回复。
- API 失败时保留待处理记录并采用有限次数、指数退避重试；插件重启后可以继续处理未完成记录。
- 数据库写入或 Embedding 失败只记录日志，不影响正常聊天。未达到分块阈值的新消息仍可通过最近对话上下文使用。

## 记忆读取与延迟控制

本地 SQLite/sqlite-vec 查询通常不是主要延迟来源，但远程查询向量 API 可能增加回复前的等待时间。因此：

- 最近消息读取与查询向量生成可以并行准备。
- 查询 Embedding 使用独立且较短的超时；超时或失败时跳过长期记忆，直接使用最近消息请求聊天模型。
- 长期记忆检索必须带群号过滤，并限制返回数量和片段长度。
- 聊天上下文设置总长度上限，优先保留当前输入和最近消息，避免历史记忆挤占模型上下文。
- 聊天请求设置超时与有限重试，失败时回复简短错误提示，不暴露密钥或内部堆栈。

## 消息触发与并发

- 仅处理 OneBot 群消息事件；私聊、群临时会话、匿名消息、系统消息和 Bot 自己发出的消息全部忽略。
- 同一 Bot 账号由其他插件发出的消息同样视为自身消息，不进入记忆。其他机器人账号没有通用可靠标识，首版提供可选的忽略 QQ 号列表，防止已知机器人之间互相回复。
- @Bot 或回复 Bot 时移除消息中的 @/回复标记后生成回复；空文本不请求模型。
- 普通文本消息始终可进入记忆流水线，但只有命中当前群概率时才触发回复。
- 概率按每条符合条件的消息独立判断；0% 表示关闭随机回复，100% 表示每条符合条件的普通文本都回复。
- 概率配置存储在数据库中，重启后保留。
- 同一群的模型请求串行处理，不同群可以并行处理。模型使用实际开始处理时的最近消息窗口，而不是消息入队时的旧快照。
- @和回复 Bot 的明确请求逐条排队并回复；随机触发在已有随机回复等待时只保留最新一条，避免模型繁忙后集中刷屏。
- `/回复概率` 和 `/清空群记忆` 等插件命令不参与随机回复，也不进入记忆。无参数查询概率与修改概率均仅 SUPERUSER 可用，非 SUPERUSER 不执行操作并收到简短权限提示。
- Bot 回复与群友消息一样进入最近窗口、长期分块和向量化，使检索到的片段保留完整问答关系；系统提示明确区分 Bot 与群友发言。

## 人格与迁移

- 首版使用可配置的中性群聊助手系统提示，要求回答自然、简洁，不假装记得未检索到的内容。
- 这是全新独立插件，不迁移现有 Qdrant、其他 Bot 或 opencode 的历史数据。

## 配置与安全

插件配置包含：

- 聊天 API 地址、密钥、模型名、请求超时。
- Embedding API 地址、密钥、模型名、查询超时。
- 数据库文件路径。
- 最近消息条数、分块消息数、长期记忆返回数及上下文长度限制。
- 默认随机回复概率（新群默认 0%）。

密钥只从环境变量或 NoneBot 配置读取，不写入数据库、日志或仓库。消息原文和向量保存在本地数据库，但会向用户配置的 Embedding 服务商发送用于向量化的文本；项目说明中必须明确这一点。

## 备选方案与取舍

### SQLite + sqlite-vec（已选择）

部署和备份简单，普通群聊规模下性能足够。消息原文与向量可以放在同一个数据库文件中，符合当前独立插件的体量。

### SQLite + Qdrant

大规模向量检索和后续扩展能力更强，但需要额外部署、监控和备份 Qdrant。当前需求没有必要承担这部分复杂度，因此不采用。

## 实现者可决定的事项

- 按现有 NoneBot2 生态选择项目结构、依赖版本和 OpenAI 兼容客户端。
- 将随机数生成封装为可替换依赖，以便测试概率边界，不在测试中依赖偶然结果。
- 在不改变上述行为的前提下确定数据库具体字段、索引和后台任务实现。
- 使用 mocked API 和真实 SQLite/sqlite-vec 编写单元与集成测试。

## 验收标准

- @Bot、回复 Bot 能使用配置的聊天模型生成回复，其他普通消息在默认配置下不回复。
- 所有群文本消息都会持久化；Embedding API 暂时不可用时，消息不丢失且聊天仍可使用最近上下文。
- 相同内容在两个群中不会互相检索；清空一个群不会影响其他群。
- 长期记忆能检索到最近窗口之外的相关聊天，且查询失败会自动降级。
- SUPERUSER 可按群设置、查询 0～100% 概率并持久化；非 SUPERUSER 无法修改或清空记忆。
- @和回复始终触发；随机概率为 0% 时不随机回复，为 100% 时所有符合条件的普通文本都回复。
- 项目标准测试、静态检查和构建通过，并使用模拟 OneBot 群消息完成端到端验证。
