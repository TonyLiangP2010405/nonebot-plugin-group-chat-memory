# 命令运行时模型配置设计

日期：2026-11-02

## 目标

将聊天 API 地址、聊天 API 密钥、聊天模型和 Embedding API 密钥四项设置从环境变量改为 SUPERUSER 私聊命令。配置全 Bot 共用，持久化保存并在更新后立即生效，无需重启。

## 命令与权限

- `/设置聊天地址 <OpenAI兼容API根地址>`：仅私聊 SUPERUSER。
- `/设置聊天密钥 <API密钥>`：仅私聊 SUPERUSER。
- `/设置聊天模型 <模型标识>`：仅私聊 SUPERUSER。
- `/设置向量密钥 <Embedding API密钥>`：仅私聊 SUPERUSER。
- `/模型配置`：SUPERUSER 可查询全局配置状态；私聊和群聊均可，但密钥只显示掩码，绝不回显完整值。

空参数、无效 URL 和无效模型标识给出简短提示。设置命令不进入插件记忆，也不触发随机回复。非 SUPERUSER 无权限执行。私聊命令仍可能存在于用户与协议端的聊天记录中，README 必须提示这一点。

## 持久化与运行时行为

- SQLite 增加全局 `runtime_config` 键值表，不与按群消息、概率或向量混用。
- 启动时从数据库加载四项配置并应用到现有共享 `Config`，因此现有 ChatClient、EmbeddingClient 和 ContextBuilder 可继续读取同一配置对象。
- 命令先成功写入数据库，再更新内存配置；数据库失败时不改变运行时行为。
- 未保存过的字段使用插件内置默认值：聊天地址和密钥为空、聊天模型为 `deepseek-v4.1-flash`、Embedding 密钥为空。
- 这四个字段不再从 `.env` 或 NoneBot 环境配置读取；`.env.example` 与 README 删除对应设置方式并改为命令说明。
- Embedding 地址、模型、超时、数据库路径及其他记忆参数维持现有配置方式，不在本次改造范围内。
- API 密钥以明文保存在本地 SQLite，数据库不加密；日志、命令响应和异常不得输出密钥。文档明确文件保护与备份风险。

## 方案取舍

### 全 Bot 共用一套运行时配置（已选择）

与现有行为一致，命令简单，只需一张全局配置表；更新即时生效。

### 每群独立 API 配置

可支持不同群使用不同模型和密钥，但私聊命令需携带群号，还要处理继承与清除，当前没有此需求，不采用。

### 命令改写 `.env`

需要写项目文件并处理重载、格式和权限，且无法自然即时生效，不采用。

## 验收标准

- 四项设置只能由 SUPERUSER 在私聊中修改，更新后无需重启即可被下一次聊天/Embedding 请求使用。
- 数据库重开后配置仍生效；同名环境变量不再影响这四项。
- `/模型配置` 不泄露完整密钥，日志和异常不包含密钥。
- 非 SUPERUSER、群聊设置、空参数和非法输入均不会改变配置。
- 原有 279 个测试保持通过，并新增命令、持久化、即时生效和脱敏测试；Ruff、编译、NoneBot 加载与构建通过。
