# 好感榜成员额外触发

日期：2026-11-03

## 目标

当本群好感榜上的群友发普通文本时，Bot 至少以 30% 的概率参与对话，不需要 SUPERUSER 先把整群 `/回复概率` 调高。

## 数据来源

`nonebot-plugin-mantou-affection` 暴露了 `service.ranking(group_id)`，返回 `RankingEntry` 列表，顺序即榜单名次。榜单长度由该插件的 `mantou_affection_ranking_size` 决定，默认 10，且只包含好感度大于 0 的成员。

本插件不读取好感度文件，也不导入该包的内部模块，只通过 `nonebot.get_plugin("nonebot_plugin_mantou_affection")` 取已加载插件的 `service`。插件未安装、未加载或读取失败时，功能自动退化为“不在榜”，不影响其他聊天逻辑。

## 触发规则

- 生效条件：普通纯文本、非回复消息，且发送者在当前群好感榜上。
- 实际概率：`max(当前群回复概率, GROUP_CHAT_MEMORY_AFFECTION_PROBABILITY)`，默认后者为 30。
- 只做一次随机判定，不会出现“先按群概率掷一次、再按好感概率掷一次”的叠加。
- 群概率高于 30% 时保持原值，不会因为上榜单而被调低。
- 仍然受每小时请求上限约束；点名消息不查询榜单，直接回复。

## 缓存

榜单查询按群缓存 30 秒。好感插件每次查询都要读 JSON 并排序，缓存后避免每条群消息都产生磁盘 IO；读取失败也在同一窗口内缓存为空，防止异常时刷日志。

## 配置

两项设置按群保存在 SQLite 的 `groups` 表中，不读取环境变量，修改后立即生效并在重启后保留。

| 命令 | 权限 | 说明 |
|---|---|---|
| `/好感概率` | 仅 SUPERUSER | 查询当前群好感榜成员的触发概率 |
| `/好感概率 <0～100>` | 仅 SUPERUSER | 设置概率，默认 30，最多一位小数 |
| `/好感开关` | 仅 SUPERUSER | 查询当前群是否启用 |
| `/好感开关 <开/关>` | 仅 SUPERUSER | 启用/停用，接受 `开/开启/on/1/true` 与 `关/关闭/off/0/false` |

新群默认启用、概率 30%。关闭开关不会清掉已设置的概率，重新开启后沿用原值。

## 方案与取舍

### 取较大概率（已选择）

实现简单、行为可预测，也不会破坏已有的 `/回复概率` 配置。

### 与群概率叠加

`1-(1-p1)(1-p2)` 会让高概率群更容易刷屏，且用户无法直观推算实际概率，不采用。

### 只按好感概率、忽略群概率

会让上榜单的群友比普通群友更少被回复（当群概率更高时），与“额外触发”的语义相反，不采用。

## 失败处理

- 好感插件缺失：`get_plugin` 返回 `None`，直接走群概率。
- `ranking` 抛异常：记录一次 warning，本次视为不在榜，后续请求在缓存窗口内不再重试。
- 用户 ID 无法转成整数：跳过该条目。
